# Task API

A production-minded REST API built with FastAPI. The project includes authentication, role-based authorization, PostgreSQL migrations, automated tests, Docker, and continuous integration.

## Features

- User registration, login, access tokens, refresh tokens, and logout from all devices
- JWT authentication with token revocation and active/inactive user handling
- Admin-only user listing, activation, and deactivation
- Product CRUD with owner-based authorization
- Product pagination, filtering, and sorting
- PostgreSQL and Alembic migrations
- Request logging, CORS, rate limiting, and health endpoints
- Pytest test suite with a 90% coverage gate in GitHub Actions
- Docker Compose environment for the API and PostgreSQL

## Tech stack

- Python 3.14
- FastAPI and Pydantic
- SQLAlchemy and Alembic
- PostgreSQL with Psycopg
- Pytest, Ruff, and GitHub Actions
- Docker and Docker Compose

## Run with Docker (recommended)

### Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- Git

### Setup

```bash
git clone https://github.com/Hayashi101/task-api.git
cd task-api
cp .env.example .env
```

Open `.env` and replace at least these placeholder values before using the project outside local development:

```text
POSTGRES_PASSWORD
DATABASE_URL
SECRET_KEY
```

For a new secret key, you can run:

```bash
openssl rand -hex 32
```

Start the API and database:

```bash
docker compose up --build
```

Docker Compose starts PostgreSQL, waits for it to become healthy, applies Alembic migrations, and then starts the API.

Open:

- Swagger UI: [http://localhost:8000/docs](http://localhost:8000/docs)
- Health check: [http://localhost:8000/health](http://localhost:8000/health)
- Readiness check: [http://localhost:8000/ready](http://localhost:8000/ready)

To stop the containers:

```bash
docker compose down
```

The PostgreSQL data remains in the Docker volume. To remove the volume and all local database data:

```bash
docker compose down -v
```

## Run without Docker

This option requires a local PostgreSQL server.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

Ensure that `DATABASE_URL` in `.env` points to your local PostgreSQL instance.

## Tests and code quality

Run the entire test suite with the coverage requirement:

```bash
python -m pytest --cov=app --cov-report=term-missing --cov-fail-under=90
```

Run linting and formatting checks:

```bash
python -m ruff check .
python -m ruff format --check .
```

## API overview

| Area | Main endpoints |
| --- | --- |
| Authentication | `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout-all` |
| Users | `POST /users/register`, `GET /users/me`, `PATCH /users/me/password` |
| Administration | `GET /users/`, `PATCH /users/{user_id}/activate`, `PATCH /users/{user_id}/deactivate` |
| Products | `GET/POST /products/`, `GET/PUT/PATCH/DELETE /products/{product_id}` |
| Operations | `GET /health`, `GET /ready` |

All product endpoints require a Bearer access token. Use `POST /auth/login` or the **Authorize** button in Swagger UI to authenticate.

## Database migrations

Create a migration after changing a SQLAlchemy model:

```bash
alembic revision --autogenerate -m "describe your change"
alembic upgrade head
```

Review autogenerated migrations before applying them, especially for schema changes on a database that contains real data.

## Deployment

The repository includes a `Dockerfile` for deployment. The container runs Alembic migrations and starts Uvicorn using the platform-provided `PORT` environment variable.

For any deployment environment, configure at minimum:

```text
APP_NAME
DEBUG=false
DATABASE_URL
SECRET_KEY
```

Never commit `.env` or deployment secrets to Git.
